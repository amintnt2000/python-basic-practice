# 📚⚡ سیستم کتابخانه با FastAPI (Library REST API)

نسخه تکامل‌یافته پروژه سیستم مدیریت کتابخانه OOP، این‌بار به‌صورت یک REST API کامل با FastAPI. منطق اصلی (کلاس‌های `Book`, `Member`, `LibraryLogic`) از پروژه OOP اولیه حفظ شده و یک لایه API روی آن قرار گرفته است.

## 🎯 هدف پروژه

نمایش نحوه تبدیل یک سیستم OOP کامل (با چند کلاس مرتبط) به یک REST API با FastAPI، همراه با مفاهیمی که در پروژه بانکی FastAPI معرفی نشده بودند: **Response Model** برای پاک‌سازی خروجی، و مدیریت دو نوع موجودیت مرتبط (کتاب و عضو) در یک عملیات واحد.

## 🏗️ ساختار پروژه

### لایه منطق (بدون تغییر نسبت به نسخه OOP)

- `Book`: مدیریت وضعیت امانت با `@property`/`@setter`
- `Member`: مدیریت لیست کتاب‌های امانت‌گرفته‌شده توسط هر عضو
- `LibraryLogic`: هماهنگ‌کننده بین کتاب‌ها و اعضا، جستجو بر اساس ISBN و شناسه عضو

### لایه API (جدید)

| متد | آدرس | توضیح |
|---|---|---|
| `POST` | `/books` | افزودن کتاب جدید |
| `GET` | `/books` | دریافت لیست همه کتاب‌ها |
| `POST` | `/members` | ثبت عضو جدید |
| `GET` | `/members` | دریافت لیست همه اعضا |
| `POST` | `/lend` | امانت دادن یک کتاب به یک عضو |
| `POST` | `/return` | پس گرفتن کتاب از یک عضو |

## 🚀 نحوه اجرا

```bash
pip install fastapi uvicorn
uvicorn main:app --reload
```

مستندات تعاملی: `http://127.0.0.1:8000/docs`

## 📋 مثال استفاده

**افزودن کتاب:**
```
POST /books
Body: {"title": "1984", "author": "George Orwell", "isbn": 1949}
```

**ثبت عضو:**
```
POST /members
Body: {"name": "Amin", "member_id": 1}
```

**امانت دادن کتاب:**
```
POST /lend
Body: {"member_id": 1, "isbn": 1949}
```

**پس دادن کتاب:**
```
POST /return
Body: {"member_id": 1, "isbn": 1949}
```

## 🧠 نکات آموزشی کلیدی

1. **Response Model برای پنهان کردن attribute های داخلی:** آبجکت `Book` دارای `_is_borrowed` (با آندرلاین) است، اما `BookResponse` فقط `is_borrowed` (بدون آندرلاین) را نشان می‌دهد. FastAPI به‌طور خودکار از طریق property مقدار درست را می‌خواند و ساختار خروجی را با مدل مشخص‌شده هماهنگ می‌کند.

2. **جستجوی همزمان دو موجودیت مرتبط:** در `/lend` و `/return`، باید هم عضو (با `member_id`) و هم کتاب (با `isbn`) به‌طور مستقل پیدا شوند و هرکدام در صورت نبود، خطای ۴۰۴ جداگانه برگردانند — پیش از آنکه عملیات اصلی (`borrow_book`/`return_book`) اجرا شود.

3. **تبدیل خطای OOP به HTTPException:** متد `return_book` کلاس `Member` در صورت پس دادن کتابی که امانت گرفته نشده، `ValueError` می‌دهد. این خطا در لایه route با `try/except` گرفته و به `HTTPException` با کد ۴۰۰ تبدیل می‌شود.

4. **متد کمکی جدید در لایه منطق:** برخلاف نسخه OOP اولیه که فقط `find_book_by_isbn` داشت، برای پشتیبانی از route های جدید، متد `find_member_by_id` نیز به `LibraryLogic` اضافه شد — نمونه‌ای از این‌که نیازهای لایه API گاهی باعث گسترش لایه منطق می‌شود.
