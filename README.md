# 🛒⚡ سیستم فروشگاه با FastAPI (Store & Cart REST API)

نسخه تکامل‌یافته پروژه سیستم فروشگاه و سبد خرید OOP، این‌بار به‌صورت یک REST API کامل با FastAPI. منطق اصلی (کلاس‌های `Product`, `Cart`, `StoreLogic`) از پروژه OOP اولیه حفظ شده و یک لایه API روی آن قرار گرفته است.

## 🎯 هدف پروژه

نمایش مدیریت **چند نمونه هم‌زمان از یک کلاس** (چند سبد خرید مختلف، هرکدام با یک `cart_id` یکتا) در قالب یک REST API — پیچیده‌ترین سناریوی مدیریت state از میان سه پروژه FastAPI این مسیر یادگیری.

## 🏗️ ساختار پروژه

### لایه منطق (بدون تغییر نسبت به نسخه OOP)

- `Product`: مدیریت موجودی انبار با `reduce_stock`/`add_stock`
- `Cart`: مدیریت آیتم‌های یک سبد خرید و محاسبه قیمت کل
- `StoreLogic`: هماهنگ‌کننده بین موجودی انبار و فرآیند تسویه حساب
- سه Custom Exception: `OutOfStockError`, `InvalidQuantityError`, `ThereIsNoItemError`

### لایه API (جدید)

| متد | آدرس | توضیح |
|---|---|---|
| `POST` | `/products` | افزودن محصول به انبار |
| `GET` | `/products` | دریافت لیست همه محصولات |
| `POST` | `/carts` | ساخت یک سبد خرید جدید (شناسه یکتا می‌گیرد) |
| `POST` | `/carts/{cart_id}/items` | افزودن یک محصول به سبد مشخص |
| `GET` | `/carts/{cart_id}` | مشاهده محتوا و قیمت کل یک سبد |
| `POST` | `/carts/{cart_id}/checkout` | تسویه حساب یک سبد خرید |

## 🚀 نحوه اجرا

```bash
pip install fastapi uvicorn
uvicorn main:app --reload
```

مستندات تعاملی: `http://127.0.0.1:8000/docs`

## 📋 مثال استفاده

**افزودن محصول:**
```
POST /products
Body: {"name": "Laptop", "price": 1000, "quantity": 5}
```

**ساخت سبد خرید:**
```
POST /carts
```

**افزودن آیتم به سبد:**
```
POST /carts/1/items
Body: {"product_name": "Laptop", "quantity": 2}
```

**تسویه حساب:**
```
POST /carts/1/checkout
```

## 🧠 نکات آموزشی کلیدی

1. **مدیریت چند نمونه با شناسه یکتا:** برخلاف پروژه‌های قبلی که فقط یک نمونه سراسری داشتند، اینجا `cart_db` یک دیکشنری از چندین سبد خرید مستقل است. هر سبد با `cart_id` یکتا (تولیدشده توسط شمارنده `next_cart_id`) شناسایی می‌شود.

2. **تفاوت بین کلاس و نمونه (instance):** یکی از رایج‌ترین اشتباهات این پروژه، صدا زدن متد از روی خود کلاس (`Cart.add_item(...)`) به‌جای نمونه واقعی پیدا‌شده از دیکشنری (`cart.add_item(...)`) بود — تفاوتی که باعث خطای اجرا می‌شود چون `self` به‌طور خودکار پر نمی‌شود.

3. **ذخیره شناسه پیش از افزایش شمارنده:** در `POST /carts`، شماره سبد ساخته‌شده باید در یک متغیر جداگانه (`current_id`) ذخیره شود پیش از افزایش `next_cart_id`؛ در غیر این صورت، در پاسخ نهایی به کلید اشتباه (که هنوز ساخته نشده) اشاره می‌شود و `KeyError` رخ می‌دهد.

4. **تفکیک چند نوع Exception مرتبط:** در `checkout`، هم `OutOfStockError` (موجودی ناکافی) و هم `InvalidQuantityError` (مقدار نامعتبر) به‌طور جداگانه گرفته و به `HTTPException` با کد ۴۰۰ تبدیل می‌شوند.
